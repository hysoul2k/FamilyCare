# Local content engine

`lib/analysis.mjs` processes only user-provided text. Zalo, Facebook and Instagram are source labels; selecting one does not connect an account, read an inbox, bypass encryption or grant API permission. Imported strings, including prompt injection or HTML, stay inert data. Consumers must render text with normal escaped UI text nodes, never `innerHTML`.

## Interfaces

- `parseImport({source, content, consent})` requires `consent === true`, a supported source (`manual`, `zalo`, `facebook`, `instagram`), and a UTF-8 decoded string at most 256 KiB. It returns `{messages, preview, count}`. JSON accepts an array or `{messages:[{text,speaker?,timestamp?}]}`. TXT treats each nonempty line as a message, with unknown speaker; it does not invent times or infer export formats. Preview contains the first five normalized messages. Maximum 5000 messages, 10000 characters per message. IDs are assigned sequentially.
- `analyzeContent(messages)` returns `{summary, observations, modelVersion, limitations}`. Deterministic Vietnamese/English keyword rules flag possible insults, threats, money/prizes, credentials and contact sharing. Each observation provides `evidenceRefs` to original message IDs and uncertainty. Obvious negation/quotation markers trigger abstention. This is a limited rule scanner, not an LLM, diagnosis, personality score or assessment that a child is safe. Empty observations mean no matching rule, not no risk.
- `trainClassifier(samples)` trains multinomial Naive Bayes from actual authorized `{text,label}` samples. The caller must enforce explicit training consent before calling. Labels are `neutral`, `bullying`, `scam`, `threat`. Minimum 20 unique examples, at least five per label. No bundled examples or default trained model are used at runtime. Unicode NFC normalization preserves Vietnamese accents. The returned JSON-serializable model contains token counts and normalized training texts for overlap checking; treat the entire model as sensitive content and delete it with its training data.
- `classifyMessages(model,messages)` returns observations with evidence IDs for non-neutral predictions with estimated probability at least 0.65. Unknown vocabulary and lower probabilities abstain. These classifier estimates are uncalibrated, not probabilities of harm. Five examples per class are an operational minimum, not evidence of reliable real-world performance.
- `evaluateClassifier(model,testSamples)` computes measured accuracy, macro F1, per-class precision/recall/support, confusion matrix and unknown-vocabulary abstentions. Exact normalized overlap with training and duplicates within the test set are rejected. Unknown-vocabulary abstentions count as incorrect for accuracy and missed for recall. F1 is macro-averaged over all four labels, including absent labels (F1 0); inspect support before comparing results.

## Evaluation and limits

Provide a separate holdout before training, split by conversation/person/source to reduce leakage. The module detects duplicate normalized text, but cannot prove independence or detect paraphrased overlap. Keep related examples in one partition. Never describe training accuracy or tiny synthetic unit fixtures as product performance; unit tests only verify algorithm behavior. Real labeled, authorized holdout data is necessary to assess utility. Linguistic bias, imbalance, slang, quoting, sarcasm and missing context can cause errors. Human review is required; no engine function takes device actions or sends text to third-party services.

Verification: `node --test tests/analysis.test.mjs`. Fixtures exist only in tests and never train a runtime model.
